Teaching Moshi when to stay silent: listening demo

Fine-tuned on 1 h (6 learning rates, 20 epochs) and 10 h (4 learning rates, 5 epochs) of synthetic conversations. For each run, the checkpoint with the lowest dev loss and the final checkpoint, plus the unmodified base model, all on the same unseen dev conversations.

How to read this

  • Pick a conversation below. Each row is one model; press play to hear it (headphones help: Moshi is on the left, the user and friend on the right).
  • Timeline: top lane = user / friend speech; bottom lane = Moshi's speech in that model's audio.
  • The shaded band is the requested silence; the vertical line is where Moshi should speak again.
  • Red Moshi speech = talking where it should be silent (after a 2.5 s grace for a short "okay").
  • Only the parts under "model generates" are the model's own choice. Elsewhere the eval replays the scripted Moshi (gray), so every hold starts from the same context.
  • Click a timeline to jump there. The text under each row is Moshi's own words stream (gray italics = replayed script).

The conversations were chosen automatically, one per behavior type, as the dev episode on which these models' outcomes differ the most. So they are harder and more contrasting than a typical episode: use the table above for the average picture and these for what successes and failures sound like.

The models

Rates are over all 80 dev_80 conversations (58 scored holds, 63 resumes, 42 ordinary questions; ±10–12 points at 95%). Dev loss = teacher-forced text loss on 200 dev conversations.
